# Project Showcase

## Goal
Present each project as a real piece of engineering work, not merely a decorative mockup.

## Process
1. Inspect existing project data, screenshots, logos, live links, repositories, and descriptions.
2. Identify what is verified and what is missing; do not invent details.
3. Select a small number of strong screenshots that show meaningful product UI.
4. Choose a layout that suits the screenshots: large editorial image, asymmetric gallery, side-by-side UI, or a compact card. Do not automatically wrap every screenshot in a phone mockup.
5. Preserve original screenshot details. Crop only when it improves composition without hiding important UI.
6. Use concise copy: project name, one-sentence purpose, a small set of relevant technologies, and available links.
7. Keep card dimensions and visual rhythm consistent while allowing screenshots to retain suitable aspect ratios.
8. Optimize image delivery according to the existing framework.
9. Verify links, alt text, responsive crops, and layout.

## Authenticity
- Never fabricate screens, app features, analytics, user counts, ratings, downloads, client relationships, or business outcomes.
- Do not present a project as deployed if no valid deployment link exists.
- Do not invent source-code URLs.
- Prefer real app screenshots and real project assets over stock photography.
- If screenshots are missing, ask for them or use existing assets; do not imply a mockup is a real screenshot.

## Output quality
A visitor should quickly understand what the project does, what is distinctive about it, and where to explore it. Avoid lengthy case studies on the homepage; use a dedicated detail page only when it adds real value.
