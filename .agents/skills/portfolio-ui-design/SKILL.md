# Portfolio UI Design

## Procedure
1. Inspect the current pages, components, styles, assets, and responsive behavior before editing.
2. Identify the main user journeys: understand the developer, explore selected projects, open project/source links, and contact the developer.
3. Audit the current design for excess copy, weak hierarchy, inconsistent spacing, generic components, decorative clutter, and redundant sections.
4. Propose a concise design direction and implementation plan before substantial changes.
5. Build on the existing framework and styling approach.
6. Establish or reuse design tokens for color, typography, spacing, content width, borders, and radii.
7. Make the primary content and selected projects the visual focus.
8. Use subtle transitions only where they provide useful feedback. Respect reduced-motion preferences.
9. Verify responsive layouts and review the final diff.

## Visual principles
- Prefer fewer, stronger elements over many weak elements.
- Use typography, alignment, whitespace, and imagery to establish hierarchy.
- Keep headings short and body copy brief.
- Use a coherent grid and consistent spacing rhythm.
- Avoid default-looking AI portfolio patterns, excessive rounded cards, gratuitous gradients, glowing borders, floating blobs, and needless scroll animations.
- Do not add a visual effect unless it serves hierarchy, usability, or brand identity.
- Preserve clear contrast and focus states.

## Content hierarchy
Prioritize a concise introduction, selected projects, relevant skills/experience, and contact/social links. Do not force every possible section into the page. Remove repetition, but preserve useful facts and functionality.

## Do not
- Invent biographical claims, metrics, testimonials, clients, or project results.
- Replace the existing stack without justification.
- redesign only the desktop view.
- treat a screenshot as permission to fabricate project UI.
- finish after changing CSS without checking the rendered result when browser tools are available.
